跟踪缓冲区

玄铁C906和C910的调试系统遵循RISC-V调试规范，核心是一个独立的调试模块（Debug Module，DM）。主机通过JTAG接口访问DM，DM再控制处理器的执行状态。JTAG接口使用标准的5线制（TCK、TMS、TDI、TDO、TRST），时钟频率通常为10-50MHz，实际项目中常用20MHz作为折中值——频率太低影响调试速度，太高则信号完整性变差。

玄铁C906/C910 JTAG接口信号定义
信号名方向功能描述
TCK输入测试时钟，所有操作同步于此沿
TMS输入测试模式选择，控制TAP状态机跳转
TDI输入测试数据输入，移位寄存器的数据来源
TDO输出测试数据输出，移位寄存器的数据出口
TRST输入测试复位，异步复位TAP状态机

调试模块内部包含一组CSR寄存器，通过抽象命令接口（Abstract Command Interface）与主机通信。主机写入命令寄存器后，DM自动执行对应的调试操作，例如读写GPR、访问内存、控制处理器运行/暂停。我在项目中踩过这个坑：调试C906时发现JTAG连接不稳定，后来排查是PCB上TCK走线过长且未做阻抗匹配，导致信号反射。将TCK频率降到10MHz后问题解决。

触发系统与硬件断点

玄铁处理器的触发系统支持多种触发类型：执行地址匹配、数据地址匹配、数据值匹配、以及它们的组合。触发点可以配置为断点（暂停执行）或观察点（记录数据）。C906提供4个触发点，C910提供6个触发点——实际开发中，4个基本够用，但如果要同时调试多核同步问题，6个会更从容。

生活类比
调试触发点就像在流水线上装了几个传感器——当某个特定工件（指令地址）经过时，传感器触发报警（暂停流水线），或者记录下当前工件的重量（数据值）。
触发点配置三要素：
  • 触发类型：选择是地址匹配还是数据值匹配，或是两者的逻辑与/或组合
  • 匹配条件：32位地址或数据值，支持掩码模式（忽略某些bit）
  • 触发动作：暂停处理器、进入调试模式、触发跟踪记录

配置触发点通过写tselect（选择触发点编号）、tdata1（配置类型和动作）、tdata2（设置匹配值）这三个CSR寄存器完成。例如，想在0x80000100处设置断点，先写tselect选择触发点0，再配置tdata1为执行地址匹配+暂停动作，最后写tdata2为0x80000100。

常见误区：
  • 触发点编号从0开始，但不同处理器对触发点数量的支持不同，写tselect时如果超出范围，返回值是0，容易让人误以为配置成功
  • 数据地址匹配时，默认只匹配低2位对齐的地址，如果要匹配未对齐访问，必须显式设置掩码
  • 在多核系统中，每个核的触发点独立配置，但调试模块只能同时响应一个核的触发——如果两个核同时命中断点，调试器会优先处理编号小的核

指令跟踪（Trace）机制

断点调试适合定位静态问题，但遇到时序敏感或偶发性故障时，靠断点反复复现效率太低。指令跟踪提供了另一种思路：处理器在运行时持续输出执行过的指令地址流，调试器离线分析这些数据，还原程序的实际执行路径。

生活类比
指令跟踪就像飞机上的黑匣子——它不干预飞行过程，只是持续记录关键数据。飞机降落后，工程师分析黑匣子数据，还原整个飞行过程中每一步操作和状态变化。

玄铁C910内置了指令跟踪模块，支持两种跟踪模式：分支跟踪和全指令跟踪。分支跟踪只记录分支指令（跳转、调用、返回等）的源地址和目标地址，全指令跟踪则记录每一条执行的指令地址。分支跟踪的数据量只有全指令跟踪的1/5左右，实际项目中90%的场景用分支跟踪就够了。

两种跟踪模式对比
特性分支跟踪全指令跟踪
数据量约为全指令的20%每条指令输出一个地址
适用场景定位分支错误、函数调用路径需要完整指令流还原
缓冲区容量需求4KB可记录约2000个分支事件4KB只能记录约500条指令
数据压缩地址差量编码逐地址输出

跟踪数据通过专用的跟踪端口输出，或者写入片内的跟踪缓冲区。C910的跟踪缓冲区大小为8KB，采用环形缓冲设计——写满后覆盖旧数据。调试时可以通过触发点控制跟踪的开始和停止，例如在某个函数入口开始跟踪，在出口停止，这样缓冲区里只保留目标函数的执行记录。

编者提示：跟踪数据的压缩算法值得关注。玄铁的分支跟踪采用差量编码——只记录当前分支地址与上次分支地址的差值，而不是完整的32位地址。差量通常只有几十到几百字节，用16位甚至8位就能表示，配合游程编码（连续相同差值合并记录），压缩比可以达到10:1以上。如果跟踪缓冲区不够用，可以尝试开启压缩选项，效果立竿见影。

调试流程与工具链

基于玄铁处理器的调试流程分为三个步骤：连接目标、配置环境、执行调试。连接目标时，调试器通过JTAG扫描链发现所有TAP（每个核对应一个TAP），然后枚举调试模块。C906和C910的JTAG IDCODE不同——C906的IDCODE低8位是0x06，C910是0x0A，这个信息在OpenOCD配置文件中会用到。

设置断点/跟踪

配置环境时，需要设置调试器的传输速率（JTAG时钟）、扫描链长度、以及每个核的调试模块基地址。C906的调试模块基地址固定为0xE0000000，C910为0xE0001000。如果使用OpenOCD，配置文件大致如下结构：

# 玄铁C910配置示例（简化）
adapter speed 20000
jtag newtap c910 cpu -irlen 5 -expected-id 0x0000000a
target create c910.cpu0 riscv -chain-position c910.cpu
c910.cpu0 configure -work-area-phys 0x80000000
riscv set_register dmcontrol 0x80000001

执行调试时，常用的操作包括：halt（暂停）、resume（恢复）、step（单步）、reg（查看寄存器）、mdw（读取内存字）。单步执行时，C906和C910的行为略有差异——C906的单步是基于指令的，一次step执行一条指令；C910则支持指令级和微指令级两种单步模式，微指令级单步可以观察流水线内部的状态变化。

这里有个隐藏的坑：调试多核C910时，如果只暂停了其中一个核，而其他核仍在运行，访问共享内存时可能出现数据不一致。正确的做法是操作前先暂停所有核，或者使用调试模块提供的原子内存访问命令。

动手试一试

  1. 用调试器连接C906开发板，读取所有CSR寄存器列表，确认调试模块是否正常工作
  2. 在0x80000120处设置一个硬件断点，运行程序观察断点是否命中，记录命中时的寄存器状态
  3. 开启分支跟踪模式，在一个循环函数中运行100次迭代，读取跟踪缓冲区数据，分析实际执行的分支路径

检验你的理解

  1. 判断题：指令跟踪模式中，全指令跟踪的数据量一定大于分支跟踪的数据量。
  2. 选择题：玄铁C910的跟踪缓冲区采用什么设计？A. 线性缓冲 B. 环形缓冲 C. 双缓冲 D. FIFO缓冲
  3. 判断题：调试多核系统时，可以只暂停一个核进行调试，其他核不受影响。

本章小结

  • 玄铁C906/C910调试系统基于RISC-V调试规范，通过JTAG接口连接调试模块，支持暂停/恢复、单步执行、断点设置等基本功能
  • 触发系统提供4-6个可配置触发点，支持地址匹配和数据值匹配，可配置为断点或观察点
  • 指令跟踪分为分支跟踪和全指令跟踪两种模式，分支跟踪数据量更小，适合定位分支错误和函数调用路径
  • 跟踪数据采用差量编码压缩，配合环形缓冲可实现连续记录，适合偶发性故障的离线分析
  • 多核调试时需注意暂停所有核后再操作共享内存，避免数据不一致
