# Handoff：FMC DDR3 转接板端到端连线独立复审

日期：2026-10-04。待审资料版本：2026-10-04-C。

## 1. 用户要求与范围

本次只审“信号是否接对、原理图是否看错、有没有错误短接/漏接”。核心问题是：**每个 MIG DDR 信号是否经过当前 FPGA 引脚和转接板，正确落到 DDR 子板 U26 的对应功能引脚上。**

不要把复审变成平台设计讨论。以下内容明确不在本次范围：

- I/O Bank、SLR、I/O 列、时钟区域、MIG 引脚规划是否合法。
- 更换系统时钟、晶振、BUFG/MMCM、250 MHz 参考来源或修改 MIG 参数。
- 高速信号完整性、等长/阻抗、工作速率、PCB 层叠与机械设计。
- AXI 地址映射、CPU/JTAG/Linux 等其他系统设计。

电源/地/NC 的**错误电气连接**仍然在范围内，例如信号误接地、12 V 误接地、两条电源网误合并。RESET_n 的既有电阻支路也在范围内，因为它属于原理图连接事实；不要求开展电源方案设计。

用户要的是可靠的对应关系资料，不要求创建原生 EDA 工程。现有 PDF/SVG 只是连线参考图，不是已布线 PCB，也不是运行过原生 EDA ERC 的工程。

## 5. 必须逐条追踪的完整链路

对每一个 DDR 位，独立建立以下链路，再与待审表比较：

```text
MIG c0_ddr3_*[bit]
  -> BD 内部网/外部接口 -> wrapper C0_DDR3_0_*[bit]
  -> 当前 XDC FPGA 球号
  -> 官方母板网络名 -> 原始母板 J2 电气针号
  -> 转接板 J1 针号 -> 转接板实际网络标签/网表
  -> 转接板 J2 针号 -> 原始子板 J4 电气针号
  -> 子板 GPIO 原始网络 -> 串联电阻/中间 DDR3_* 网络（如有）
  -> U26 实际球号 -> U26 对应功能（A0、DQ0、CK、DQS0 等）
```

不仅检查“接到了某个 DDR 球”，还要检查“接到了同一位/正确功能”。地址与数据的位交换、CK/DQS 极性翻转、DM/DQS 字节串换，都应报告。

应穷举 50 个 DDR 接点：

- 地址 A0–A15：16；BA0–BA2：3。
- RAS_n、CAS_n、WE_n、CS_n、CKE、ODT、RESET_n：7。
- CK_P/CK_N：2。
- DQ0–DQ15：16；DM0/DM1：2；DQS0_P/N、DQS1_P/N：4。

不能只抽查时钟或低字节。DQ/DQS 是双向，其他 DDR 接点是 MIG 输出；“从 MIG 出来”是端到端接线描述，不代表读操作时 DQ 也是输出。

## 6. 本次最重要的防错方法

### 6.1 针号/文字错位

子板原始 PDF 的接插件符号内部蓝色文字与实际引线存在错位；U26 的内部功能文字也不能只按视觉最近的一行直接配对。

应放大原图，以**外侧黑色电气针号/球号及对应实际引线**定位端点，追到网络文字和器件功能。不要用 PDF 提取文本的先后顺序判断针号关系，也不要把某个邻近文字误当作本线标签。

文字与引线仍有歧义时，要查看矢量坐标、原生符号或对应颗粒手册。不能仅因颜色/上下邻近便武断认定。证据不充分就列“待确认”，不要用当前 JSON 填补源图证据。

### 6.2 数据别名、串联电阻与字节归属

在子板第 4 页追踪：

- RN7–RN10：GPIO 到 DDR3_D0–DDR3_D15 的串联通路。
- RN11：GPIO 到两组 DDR3_DQS_P/N 的串联通路。
- RN25：GPIO 到 DDR3_DM0/DM1 的串联通路。
- 再从这些 DDR3_* 网络追到 U26 的外侧球号和 DQ/DQS/DM 功能。

以上位号是现有图中的导航线索，仍需独立确认每个支路；不能只读取 J4 到 GPIO 就宣布整条 DQ 链路正确。

低字节应为 DQ0–7 + DM0 + DQS0_P/N，高字节为 DQ8–15 + DM1 + DQS1_P/N。单端地址/DQ 的原始 `LAxx_P/N`、`GPIO*_P/N` 名称不代表 DDR 差分对，也不能按 P/N 名称自动重排位序。

### 6.3 短路/漏接检查要按节点关系做

- 检查每个 MIG 位、FPGA 球号、两端 FMC 信号接点是否唯一，有无遗漏或重用。
- 检查 XDC 是否有重复/覆盖的 PACKAGE_PIN 设置，是否其他顶层信号也占用同一球号。
- 每条 DDR 转接板网络应只有一端 J1 和一端 J2；检查是否两个不同 DDR 网误同名，或某个针同时列在 DDR 与 GND/电源中。
- 检查跨页同名全局标签是否真的应互连；重复画出的连接器分部不是不同器件，重复标签可能合并网络。
- 检查实际图面的线端是否落在正确针脚；交叉线是否有连接点；NC 叉号是否与导线/标签矛盾。不能只检查网表而不看图。
- 检查所有 GND、3V3、VADJ 接点，并检查剩余 NC：不允许标准 FMC 地针模板覆盖子板实际 NC；不允许顶底同号焊盘隐含直通。
- 母板 C35/C37 的 12 V、D1 的 PGOOD 与子板对应网必须分别追踪，检查是否意外连接到 GND、3V3、VADJ 或信号。
- 电阻阵列的各支路不是一个共用网络；串联电阻不是断路；两个信号各经电阻接 VTT，不等于两者被直接短接。通过元件形成的连接和零欧直连要分别记录。
- 检查 RN28 的 RESET_n 支路与 R_RESET：确认属于电阻终端/下拉关系，不误报为导线短路，也不遗漏会影响复位的原图支路。
- 若某个源图接点只有悬空引线且没有 NC 叉号，区分“未连接”与“明确标 NC”；必要时列待确认，不擅自补成地。

## 8. 已有检查脚本的盲点

上一次 `verify_pinmap.ps1` 与 `audit_subcard_source.py` 都通过，PDF 11 页也做过图面复查。这是历史记录，不是本次复审结论。

- `connections.md`、网表、PDF、SVG 都由 `pinmap.json` 生成；它们之间一致是同源一致性，不是独立证据。
- `verify_pinmap.ps1` 主要检查 wrapper 位集合、XDC、官方 XDC 与映射/网表，不完整追踪 MIG 内部 HDL 到 U26 的每个功能，也不能证明图面导线没有落错。
- `audit_subcard_source.py` 用固定颜色、坐标阈值、手工指定地总线 X 坐标读取特定源 PDF。不能把它当作通用电气拓扑/ERC 工具，需质疑它自己的假设。
- 该脚本核对的是母板 50 对接点/网络与子板 J4 400 针引线、地总线、50 对 GPIO 网络；它没有自动验证 GPIO 经电阻/DDR3_* 别名到 U26 的整个数据链路，也没有完整验证跳线电源短接组合。
- 该脚本在没有附着导线时会将接点记为未连接，即使没有 NC 叉号；这一分类需人工确认。
- 旧 `validation/` 中综合/实现/DRC 报告属于旧方案，不能用来替代当前原理图信号审核；本次无需阅读或重新运行这些物理报告。

建议先从原始证据独立建立端到端表，再对照上述脚本及待审产物，减少被既有数据带偏的风险。
