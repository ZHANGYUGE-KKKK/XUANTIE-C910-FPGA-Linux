# 整数单元（IU）RTL 结构报告

## 1. 范围与结论

本文完整覆盖 `gen_rtl/iu/rtl` 下的 14 个 Verilog 文件，入口为 `ct_iu_top`。连接关系按真实 `module`、实例化语句和具名端口连接追踪；跨目录模块只记录为边界，不展开其 RTL。当前目录没有本目录内部使用的预处理指令（include、define、ifdef），主要配置以端口选择、局部 `parameter`、门控时钟和外部模块接口体现。

IU 是一个双整数发射管线加分支/PCFIFO 的执行子系统：

```text
ct_iu_top
├─ ct_iu_alu x_ct_iu_alu0             pipe0 ALU
├─ ct_iu_alu x_ct_iu_alu1             pipe1 ALU
├─ ct_iu_bju x_ct_iu_bju              分支、跳转、预测校验、PCFIFO
│  └─ ct_iu_bju_pcfifo
│     ├─ ct_iu_bju_pcfifo_entry ×32   PCFIFO 实体项
│     └─ ct_iu_bju_pcfifo_read_entry ×3  RTU pop/read 缓冲项
├─ ct_iu_mult x_ct_iu_mult            pipe1 乘法
│  └─ multiplier_65x65_3_stage        65×65、3 级乘法器
├─ ct_iu_div x_ct_iu_div              pipe0 迭代除法
│  ├─ ct_iu_div_srt_radix16           radix-16 SRT 控制/结果处理
│  │  └─ ct_vfdsu_srt_radix16_only_div  外部向量/浮点目录模块
│  └─ ct_iu_div_entry                  2 项除法结果缓存
├─ ct_iu_special x_ct_iu_special      AUIPC/ECALL/EBREAK/VSETVL*
├─ ct_iu_cbus x_ct_iu_cbus            完成、异常、flush 汇聚到 RTU
└─ ct_iu_rbus x_ct_iu_rbus            结果写回、EX1 forwarding、preg expand
```

`ct_iu_top` 的输入侧主要来自 IDU、IFU、CP0、RTU、MMU、VFPU 和 HAD；输出侧主要回到 IDU、IFU、RTU、VFPU 和 HAD。IU 顶层端口列表中没有 `iu_lsu_*` 或 `lsu_iu_*` 数据端口，因此 IU 与 LSU 不存在本目录中可见的直接数据/地址通道；LSU 的提交与异常协调由 RTU/CP0 边界完成（`ct_iu_top.v:17-266`）。

## 3. 顶层边界和端口分组

### 3.1 IDU → IU：RF/发射输入

`ct_iu_top` 的 IDU 输入分成三个 RF pipe：

- pipe0：ALU、DIV、SPECIAL 共享的整数输入，包括 `src0/src1/src1_no_imm/src2[63:0]`、`func[4:0]`、`rslt_sel[20:0]`、`dst_preg[6:0]`、`iid[6:0]`、异常标记、立即数和向量 MTVR 元数据，见 `ct_iu_top.v:295-329`。
- pipe1：ALU1/乘法输入，包括 `mult_func[7:0]`、`mla_src2_preg[6:0]`、`mla_src2_vld`、两个 64-bit 源操作数和目标 preg，见 `ct_iu_top.v:330-351`。
- pipe2：BJU 输入，包括 `func[7:0]`、IID/PID、PC 相对 offset、源操作数、pcall/rts、指令长度和 VL 元数据，见 `ct_iu_top.v:352-363`。

各单元使用独立的 `*_sel` 与 `*_gateclk_sel`。这两个信号同时承担发射有效性和局部门控时钟唤醒条件，不能仅将 `sel` 理解为结果选择。

IDU 还接收 IU 的相关性与资源反馈：ALU EX1 forwarding、pipe0/pipe1 EX2 写回 preg/data/vld、五路 preg/vld duplicate、乘法 EX1 stall、除法 busy/wb-stall/结果 preg duplicate、BJU mispred stall 以及 PCFIFO 分配 PID，顶层输出定义见 `ct_iu_top.v:401-460`。

### 3.2 IFU ↔ BJU/PCFIFO

IFU 向 IU 提供两路 PCFIFO create 记录，每路含 `cur_pc/tar_pc[39:0]`、`chk_idx[24:0]`、BHT prediction、JAL/JALR、目标寄存器有效和 jump mispredict，见 `ct_iu_top.v:366-385`。`ct_iu_bju_pcfifo` 将两路 IFU 记录编码后最多扩展为三个内部 create 项；其中 `CENTRY_WIDTH=110` 的打包字段为 `cur_pc[39:0]`、`tar_pc[79:40]`、BHT、JAL/JALR、dst_vld、jmp_mispred 和 `chk_idx[109:85]`，见 `ct_iu_bju_pcfifo.v:1677-1693`。

IU 返回 IFU：

- BJU change-flow：`chgflw_vld`、目标 PC、当前 PC、BHT 检查结果、条件分支 taken、预测和 `chk_idx`；端口宽度见 `ct_iu_top.v:461-472`，实际赋值见 `ct_iu_bju.v:1003-1019`。
- `iu_ifu_pcfifo_full`：PCFIFO 满时阻止继续创建；满判断为 32 项 valid 与 create pointer 的重叠，见 `ct_iu_bju_pcfifo.v:2203-2239`。
- BJU/PCFIFO 产生的 `iu_idu_pcfifo_dis_inst0_pid` 至 `inst3_pid` 回到 IDU，用于 pipe2 指令与 PCFIFO 项匹配，见 `ct_iu_bju_pcfifo.v:2060-2124`。

只有较老的 BJU 指令允许驱动 change-flow；BJU 用 older IID 比较和 `rtu_iu_flush_chgflw_mask` 屏蔽不应生效的跳转，见 `ct_iu_bju.v:485-506`、`752-765`。

### 3.3 IU → RTU：完成/异常（Cbus）

`ct_iu_cbus` 的 pipe0 完成源包括 IDU pipe0、DIV、SPECIAL、CP0 EX3 和 VFPU pipe6；pipe1 包括 IDU pipe1、MUL 和 VFPU pipe7；BJU 单独作为 pipe2 完成源，实际源选择见 `ct_iu_cbus.v:296-374`、`507-580`。输出到 RTU 的信息包括：

- pipe0：`cmplt/iid`、abnormal、exception valid/vector、high hardware exception、breakpoint、flush、instruction MMU exception、`mtval`、exception PC、VSETVL 和 vstart；赋值见 `ct_iu_cbus.v:485-499`。
- pipe1：`cmplt/iid`，见 `ct_iu_cbus.v:507-568`。
- pipe2：BJU `cmplt/iid`、abnormal、JMP mispredict 和 BHT mispredict，直接转发自 BJU EX2，见 `ct_iu_cbus.v:575-580`。

`ct_iu_top` 把这些信号作为 `iu_rtu_pipe*`、`iu_rtu_pcfifo_pop*` 以及 `iu_rtu_ex2_pipe*_wb_preg_*` 输出，端口定义见 `ct_iu_top.v:473-501`。

### 3.4 IU → IDU：结果写回、forwarding 和 stall

`ct_iu_rbus` 的实际结果源如下：

| 写回通道 | 结果来源 | 时序/作用 |
|---|---|---|
| pipe0 | ALU0、DIV、SPECIAL、CP0 EX3、VFPU pipe6 | 结果有效信号在 pipe0 rbus 汇聚，并复制成 5 路 IDU duplicate 和 1 路 IDU 主写回，再提供 1 路 RTU valid；见 `ct_iu_rbus.v:318-405`、`440-492`。 |
| pipe1 | ALU1、MUL、VFPU pipe7 | MUL 的 valid 在 EX3、data 在 EX4；写回 data 对 `mult_rbus_ex4_data_vld` 做选择，见 `ct_iu_rbus.v:500-566`、`601-655`。 |
| EX1 forwarding | 仅 ALU0/ALU1 的 `fwd_data/fwd_vld/preg` | 直接回 IDU；DIV/MUL/SPECIAL 不通过该 EX1 forwarding 口，见 `ct_iu_rbus.v:489-492`、`652-655`。 |

所有整数结果数据是 64 bit，preg 是 7 bit；`ct_rtu_expand_96` 把结果 preg 扩展为 96-bit one-hot/expanded 表示，实例见 `ct_iu_rbus.v:407-412`、`568-573`。因此写回接口同时存在 7-bit 标量 preg、96-bit expanded preg、64-bit data 和多路 valid duplicate。

## 4. 各功能单元的真实数据路径

### 4.1 ALU：pipe0/pipe1 对称实例

`ct_iu_top` 以同一个 `ct_iu_alu` 分别实例化 ALU0 和 ALU1，实例端口通过 `pipex→pipe0/pipe1` 规则映射：ALU0 见 `ct_iu_top.v:824-864`，ALU1 见 `866-906`。ALU 的 21-bit `rslt_sel` 将结果分为：

- adder：ADD、ADDW、SUB、SUBW、SLT；
- shifter：左/右移、字宽移位和扩展；
- logic：AND、OR、XOR、LUI、CLI；
- misc：MV、TSTNBZ、TST、FF1、REV、REVW；
- 额外的 max/min/addsl 选择。

选择常量见 `ct_iu_alu.v:229-257`。源操作数和选择信号在 RF/EX1 锁存，结果数据与 valid 在 EX1 输出，局部门控、RF/EX1/EX2 寄存见 `ct_iu_alu.v:265-425`；结果选择和 forwarding 输出见 `928-1043`。ALU 还把 MTVR 指令、目标 vreg、VL/VLMUL/VSEW、EX2 源操作数送给 VFPU，见 `ct_iu_alu.v:1048-1091`。

### 4.2 BJU：分支结果与 PCFIFO 的双路径

BJU 从 IDU pipe2 锁存 IID、func、两个源操作数、offset、当前 PC/PID、预测信息和 VL 元数据；RF/EX1 锁存见 `ct_iu_bju.v:514-609`。条件比较覆盖 BEQ/BNE/BLT/BLTU/BGE/BGEU，`func[6]` 区分 branch/JAL，`func[7]` 区分 jump/JALR，见 `ct_iu_bju.v:617-661`。目标地址、JALR 规范化、MMU/canonical 地址检查和 mispredict 判断见 `666-765`。

BJU 的时间顺序为：

1. EX1 完成分支条件、目标 PC、BHT/jump mispredict 和 older-IID 约束。
2. EX2 锁存 `abnormal/mispred/target/current PC/check idx/PID`，产生 PCFIFO 写入字段和 RTU pipe2 complete，见 `ct_iu_bju.v:858-997`。
3. EX2 change-flow 输出给 IFU，并产生 `iu_yy_xx_cancel`；EX3 保留 bypass 元数据供 PCFIFO/RTU 在 pop 时旁路，见 `ct_iu_bju.v:1003-1116`。

PCFIFO 的 entry 使用 67-bit 内部 RF 数据和 51-bit RTU pop 数据；字段包括 cmplt、flush、valid、length、BHT/BJU 预测、mispredict、跳转类型和 40-bit PC，见 `ct_iu_bju_pcfifo_read_entry.v:153-185`。32 个 entry 的 valid/completion 位分别位于 `PCFIFO_VLD=48`、`PCFIFO_CMPLT=50`，参数定义见 `ct_iu_bju_pcfifo.v:617-621`。RTU 有三个 pop/read entry，数据输出为 48 bit（去除内部控制位），顶层端口见 `ct_iu_top.v:477-479`。

PCFIFO 具有三套指针语义：create pointer 接收 IFU 记录，assign pointer 给 IDU 分配 PID，pop pointer 按 RTU 读取数量前进；指针与 flush 重对齐逻辑见 `ct_iu_bju_pcfifo.v:1931-2116`、`2705-2778`。在 entry 已完成且匹配 EX2/EX3 BJU PID 时，PC 可以从 BJU bypass 路径直接返回 RTU，否则经 read entry 返回，选择见 `2783-2882`。

### 4.3 乘法：pipe1 的 EX1→EX4 长管线

乘法只连接 IDU pipe1；顶层实例端口和回传握手见 `ct_iu_top.v:995-1028`。`ct_iu_mult` 在 EX1 根据 `mult_func` 对两个 64-bit 源扩展为 65-bit 有符号/无符号操作数，并支持 MLA 的第三操作数，见 `ct_iu_mult.v:293-316`。MLA 的 src2 依据 EX1/EX2/EX3 结果 preg 比较进行 forwarding，见 `321-342`。

乘法管线为：

```text
RF/EX1  →  EX2  →  EX3  →  EX4
  锁存       乘法器/中间状态     valid/preg → rbus   64-bit data → rbus
```

EX1 valid 同时作为 `iu_idu_ex1_pipe1_mult_stall`，见 `ct_iu_mult.v:347-358`；EX2 的 valid/preg duplicate 返回 IDU，见 `433-505`；EX3 输出 `mult_rbus_ex3_data_vld/preg`，EX4 输出结果数据，见 `521-609`。结果选择支持低 64 位乘积、high 64 位乘积和 MULW 符号扩展，见 `648-661`。

`multiplier_65x65_3_stage` 使用 Booth 部分积、压缩树和两组时序寄存：L1 在 `pipe1_clk` 注册，L5 在 `pipe2_clk` 注册，最终拼出 `product={product_mult[129:64], product_mult_add[63:0]}`，见 `multiplier_65x65_3_stage.v:57-98`、`304-351`、`459-510`。

### 4.4 除法：单发射 FSM、radix-16 SRT 和 2 项缓存

除法只从 pipe0 发射。`ct_iu_div` 的状态机为 `IDLE → DIV_RF → EX1 → EX2 → EX3 → REQ → DIV_WF_WB → DIV_WB`，状态定义和转移见 `ct_iu_div.v:225-388`。输入 `func[0]` 指示 signed，`func[1]` 指示 word width，`func[3]` 指示 quotient/remainder 选择；EX1 锁存源操作数、IID、目标 preg 和五路 preg duplicate，见 `ct_iu_div.v:396-426`。

EX1 首先处理 signed/word 的绝对值、除零和有符号溢出；若操作数与两个缓存项完全匹配则直接命中缓存，匹配条件见 `ct_iu_div.v:892-927`。未命中时，`ct_iu_div_srt_radix16` 接收归一化 dividend/divisor、位移和指数，调用外部 `ct_vfdsu_srt_radix16_only_div` 迭代；实例和 SRT 时钟见 `ct_iu_div.v:1035-1057`、`ct_iu_div_srt_radix16.v:132-226`。结果按 signed/word 重新符号扩展，并选择商或余数，见 `ct_iu_div.v:1086-1102`。

`ct_iu_div_entry` 提供 2 项 258-bit 缓存，每项打包 `src0[63:0]`、`src1[63:0]`、quotient[63:0]、remainder[63:0]、signed 和 word 标志；写入只在非特殊结果的 DIV_WB 阶段发生，见 `ct_iu_div.v:1107-1157`。除零、溢出和指数位移为零的结果固定值见 `1160-1177`，最终结果 mux 见 `1217-1251`。

除法结果仅进入 pipe0 rbus：`div_rbus_pipe0_data_vld=div_wb0_inst_vld`，数据为 quotient 或 remainder，见 `ct_iu_div.v:1256-1273`。`iu_idu_div_busy`、`iu_idu_div_wb_stall` 和 `iu_idu_div_inst_vld` 分别反映 FSM 活动、等待写回和完成，见 `380-388`、`1259-1264`。

### 4.5 Special：异常型控制指令与向量配置更新

Special 的 `func` 参数编码 NOP、ECALL、EBREAK、AUIPC、pseudo-AUIPC、VSETVLI 和 VSETVL，见 `ct_iu_special.v:226-232`。AUIPC 使用特殊立即数与 BJU 当前 PC，形成 64-bit rbus 结果；VSETVL* 根据 AVL、VLMUL/VSEW、CP0 的 VL/VILL/VSTART 计算新 VL，并输出异常/flush/mtval/vstart 信息，计算与选择见 `354-511`。

Special 的异常输出包含 instruction valid、exception valid/vector、abnormal、breakpoint、flush、high hardware exception、instruction MMU exception、IID、mtval、VSETVL 和 vstart，连接至 cbus 的 EX1 输入，见 `ct_iu_special.v:587-646`。AUIPC/VSETVL* 的 64-bit 结果进入 special rbus，见 `651-659`。

## 5. Cbus、Rbus 与握手关系

```text
IDU pipe0 ─┐
DIV -------┤
SPECIAL ---┤── ct_iu_cbus ──> RTU pipe0 complete/exception
CP0 EX3 ---┤
VFPU p6 ---┘

IDU pipe1 ─┐
MUL -------┤── ct_iu_cbus ──> RTU pipe1 complete
VFPU p7 ---┘

ALU0/DIV/SPECIAL/CP0/VFPU6 ──> rbus pipe0 ──> IDU + RTU WB
ALU1/MUL/VFPU7             ──> rbus pipe1 ──> IDU + RTU WB
BJU EX2                    ──> cbus pipe2 ──> RTU + IFU change-flow
```

Cbus 的 valid 由发射选择与各功能单元完成条件组合而来，并在 gated clock 下锁存；pipe0 异常/数据分别由独立门控时钟保持，见 `ct_iu_cbus.v:268-417`。Rbus 的结果 valid 先聚合为 pipe0/pipe1 的 7 路 WB valid（5 路 IDU duplicate、1 路 IDU 主写回、1 路 RTU），再锁存数据和 preg，见 `ct_iu_rbus.v:290-344`、`440-485`、`500-524`、`601-647`。

需要特别区分两类握手：

- forwarding 是 ALU EX1 的低延迟 data/preg/vld，服务 IDU 下一周期相关性判断；
- writeback/complete 是 rbus/cbus 的结果或退休条件，可能来自更晚的 MUL/DIV/VFPU/CP0 路径，不能用 EX1 forwarding valid 替代。

## 6. 时钟、复位和 flush

### 6.1 时钟结构

所有 IU 子模块以 `forever_cpuclk` 为输入，并由 `cp0_yy_clk_en`、`cp0_iu_icg_en`、局部 enable 和 `pad_yy_icg_scan_en` 控制 `gated_clk_cell`。`ct_iu_top` 将 `cpurst_b`、`forever_cpuclk`、全局/模块门控信号统一连接到各实例，见 `ct_iu_top.v:826-1256`。

- ALU：ctrl、EX1、EX2 三类 gated clock，见 `ct_iu_alu.v:265-322`。
- BJU：PCFIFO entry/create/pop/assign 时钟以及 BJU EX1/EX2/EX3，见 `ct_iu_bju.v:516-861`、`ct_iu_bju_pcfifo.v:1698-1755`、`1932-2064`、`2707-2723`。
- MUL：模块、EX1、EX2、EX3、EX4 五类局部门控时钟，见 `ct_iu_mult.v:186-283`。
- DIV：DIV FSM、EX1、EX2，以及 SRT 和 SRT-div 时钟，见 `ct_iu_div.v:238-295`、`ct_iu_div_srt_radix16.v:132-226`。
- Cbus/Rbus/Special/PCFIFO entry：均有 valid/data/entry 级门控时钟，分别见 `ct_iu_cbus.v:268-417`、`ct_iu_rbus.v:290-420`、`ct_iu_special.v:240-276`、`ct_iu_bju_pcfifo_entry.v:158-218`。

### 6.2 复位和 flush

`cpurst_b` 是各时序块的异步低有效复位，清除 valid、状态机、preg duplicate、指针和异常保持寄存器。`rtu_yy_xx_flush` 是运行时全局 flush：

- ALU、MUL、Special、Cbus、Rbus 在各自 valid/数据寄存块中清除或阻止错误路径继续传播，证据分别见 `ct_iu_alu.v:331-345`、`ct_iu_mult.v:347-403`、`ct_iu_special.v:281-338`、`ct_iu_cbus.v:296-317`、`ct_iu_rbus.v:318-333`。
- DIV 在全局 flush 时回到 IDLE，SRT 关闭并清除迭代上下文，见 `ct_iu_div.v:315-323`、`1059-1071`；DIV entry 的禁用清除由 `cp0_iu_div_entry_disable_clr` 控制，见 `ct_iu_div_entry.v:121-181`。
- BJU 将全局 flush、前端 flush 和 change-flow cancel 分开处理；`rtu_iu_flush_fe` 会使 IFU/PCFIFO 侧未退休项失效，`iu_yy_xx_cancel` 由有效 change-flow 产生，见 `ct_iu_bju.v:773-839`、`1003-1008`。
- PCFIFO 在 cancel/flush 时重置 create/assign/pop 相关指针或清除 entry，避免错误路径的 PC 记录进入 RTU，见 `ct_iu_bju_pcfifo.v:1763-1820`、`2060-2116`、`2728-2772`；单项状态条件见 `ct_iu_bju_pcfifo_entry.v:277-331`。

`rtu_iu_flush_chgflw_mask` 只屏蔽 BJU change-flow，不等同于全局 `rtu_yy_xx_flush`；`rtu_iu_rob_read*_pcfifo_vld` 则驱动 RTU pop/read 侧，不能视作写回 valid。

### 7.3 宏和外部依赖结论

对 `gen_rtl/iu/rtl` 搜索后，没有发现本目录内的 include、define、ifdef 配置分支；因此不能从该目录推导 cache、TLB、核数等系统宏。IU 的编译/工程配置应在上层 filelist、生成器或 Vivado 工程中确认。本目录明确依赖但未定义的模块包括：

- `gated_clk_cell`：时钟门控标准单元；
- `ct_rtu_expand_96`、`ct_rtu_expand_32`、`ct_rtu_encode_32`、`ct_rtu_compare_iid`：RTU 公共编码/比较模块；
- `ct_vfdsu_srt_radix16_only_div`：SRT radix-16 除法核心；
- `booth_code` 及乘法压缩树使用的局部/外部乘法结构。

这些模块只作为 IU 的集成边界记录，未把它们误归入 `gen_rtl/iu/rtl` 的 module 树；实例证据见 `ct_iu_div_srt_radix16.v:172-200`、`ct_iu_bju.v:485-506`、`ct_iu_bju_pcfifo.v:1987-2124`、`ct_iu_rbus.v:407-412`。

## 8. 调试与观测

`ct_iu_top` 输出 10-bit `iu_had_debug_info`。当前实现明确映射：bit0=PCFIFO full，bit1=DIV 非 idle，bit2=DIV 等待写回，bit9:3=BJU mispredict IID，见 `ct_iu_top.v:1259-1265`。这组信号只用于 HAD 观测，不参与完成、写回或 flush 控制。

## 9. 关键结论

1. IU 的真正结果汇聚点是 `ct_iu_rbus`，真正退休/异常汇聚点是 `ct_iu_cbus`；两者分别处理“数据可用”和“指令可提交”，不能合并理解。
2. ALU 的 forwarding 只提供 EX1 低延迟路径；MUL、DIV、SPECIAL、CP0、VFPU 的结果通过 rbus 的对应 pipe/时序返回 IDU/RTU。
3. BJU 同时维护分支执行结果和 IFU→IDU→RTU 的 PCFIFO 记录；PCFIFO 的 32 项容量、PID 分配和 pop 指针是分支退休顺序的关键状态。
4. DIV 是 pipe0 的单发射、可缓存命中、radix-16 迭代单元；`busy/wb_stall/inst_vld` 是 IDU 与 DIV 之间的资源和结果握手。
5. 全局 flush 使用 `rtu_yy_xx_flush`，前端路径还使用 `rtu_iu_flush_fe`、`rtu_iu_flush_chgflw_mask` 和 BJU 产生的 `iu_yy_xx_cancel`；这四类控制信号的作用域不同。
6. 该目录没有直接 LSU 端口；对 LSU 的边界应继续在 `ct_core`/RTU/CP0 层追踪，而不能在 `ct_iu_top` 内虚构一条 IU-LSU 数据路径。
