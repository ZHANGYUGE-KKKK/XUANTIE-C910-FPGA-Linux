# L2 Cache RTL 结构说明

## 1. 范围与结论

本文基于 `gen_rtl/l2c/rtl` 下全部 RTL 文件，并补充核对了 CIU 对接处
`gen_rtl/ciu/rtl/ct_ciu_l2cif.v` 与默认宏文件 `gen_rtl/cpu/rtl/cpu_cfig.h`。
本文只描述现有代码，不代表对注释中被裁剪的生成模板功能作补全。

结论如下：

- L2 顶层 `ct_l2c_top` 是两个完全对称的、各自拥有 tag/status/data RAM
  的 sub-bank，另有一个跨两个 bank 共享的 prefetch 单元。
- 每个 sub-bank 是 16-way 组相联 cache；默认配置为 `L2_CACHE_16WAY`、
  `L2_CACHE_1M`。按代码计算，单 bank 为 512 sets × 16 ways × 64B =
  512KiB，两个 bank 合计 1MiB。
- 一条 cache line 的数据通路为 512 bit，由四个 128 bit data SRAM slice
  拼成；tag 为每 way 一项，status/dirty 为每 way 8 bit，另有 16 bit
  replacement/FIFO 状态。
- 普通访问由 CIU/SNB 提供地址和写数据；命中返回 CIU，缺失时的 refill
  数据仍由 CIU/SNB 侧送入 L2。L2 不直接暴露 BIU 或外部内存端口；dirty
  line 的回写请求由 ICC 产生，经 CIU 的 VCTM/VB 路径送向外部写回通道。
- ECC 接口保留在端口和流水级中，但本目录的 tag ECC decoder/encoder 实例
  均为注释，纠正信号是直通，fatal error 被固定为 0；data ECC 也只保留
  第五个 RAM 选择位，没有实际 data-ECC array 实例。
- 本目录没有 MBIST 控制器或 MBIST 端口。可见的低功耗机制是 gated clock、
  RAM clock-enable、`l2c_icg_en` 和 scan enable；`no_op` 只表示逻辑空闲。

证据：`gen_rtl/l2c/rtl/ct_l2c_top.v:525-696`、
`gen_rtl/l2c/rtl/ct_l2c_sub_bank.v:390-412`、
`gen_rtl/cpu/rtl/cpu_cfig.h:214-219`、
`gen_rtl/ciu/rtl/ct_ciu_l2cif.v:1060-1184`。

## 3. 容量、way 和 SRAM 组织

### 3.1 默认宏配置

`cpu_cfig.h:214-219` 定义了 `L2_CACHE_16WAY` 和 `L2_CACHE_1M`。在
16-way 分支中，`cpu_cfig.h:377-418` 给出以下参数；`TAG_INDEX_WIDTH`
是每 bank 的 set 地址宽度，`TAG_DATA_WIDTH` 是每 way 的 tag 位数，
`DATA_INDEX_WIDTH` 是 data array 的地址宽度。

| 宏容量 | 每 bank sets | tag/way | tag SRAM（4-way × 4） | dirty SRAM | data SRAM（每 slice） | data index |
|---|---:|---:|---|---|---|---:|
| `L2_CACHE_128K` | 64 | 27 | 64×108 | **无对应 64×144 wrapper** | 1024×128 | 10 |
| `L2_CACHE_256K` | 128 | 26 | 128×104 | 128×144 | 2048×128 | 11 |
| `L2_CACHE_512K` | 256 | 25 | 256×100 | 256×144 | 4096×128 | 12 |
| `L2_CACHE_1M` | 512 | 24 | 512×96 | 512×144 | 8192×128 | 13 |
| `L2_CACHE_2M` | 1024 | 23 | 1024×92 | 1024×144 | 16384×128 | 14 |
| `L2_CACHE_4M` | 2048 | 22 | 2048×88 | 2048×144 | 32768×128 | 15 |
| `L2_CACHE_8M` | 4096 | 21 | 4096×84 | 4096×144 | 65536×128 | 16 |

其中 tag array 的每行宽度为 16 × `L2C_TAG_DATA_WIDTH`，dirty/status array
固定为 16 × 9 bytes = 144 bit。`ct_l2cache_tag_array_16way.v:34-38`、
`ct_l2cache_dirty_array_16way.v:33-40`、`ct_l2cache_data_array.v:35-43`
分别声明这些参数化端口。

默认 1MiB 组织为：每 bank 的 4 个 `8192×128` data SRAM 各含 128KiB，
合计 512KiB；两个 bank 合计 1MiB。16-way tag 为 `512×96`，dirty/status
为 `512×144`。这是按 RAM 深度、宽度和四个 data slice 的实例连接推导的，
不是额外的容量寄存器。

### 3.2 cache array 连接

- `ct_l2cache_top.v:109-117` 实例化一个 `ct_l2cache_tag_array_16way`，
  tag 输入/输出宽度为 384 bit（16 × 24 bit，默认 1M）。
- `ct_l2cache_top.v:130-138` 实例化一个
  `ct_l2cache_dirty_array_16way`，宽度为 144 bit。
- `ct_l2cache_top.v:157-230` 实例化四个相同的
  `ct_l2cache_data_array`。每个使用一个 128 bit data slice，分别连接
  `l2c_data_dout[127:0]`、`[255:128]`、`[383:256]`、`[511:384]`；四个
  slice 使用独立的 `data_cen`、`data_wen`，但共享 data clock。
- `ct_l2cache_top.v:150-154` 把四个外部 bit 写使能扩展为四个 128 bit
  写 mask；`ct_l2cache_data_array.v:60-100` 根据容量宏选择 data SRAM。
- `ct_l2cache_tag_array_16way.v:61-191` 将 16 ways 分成四个 SRAM wrapper，
  每个 wrapper 承载连续 4 ways；`ct_l2cache_dirty_array_16way.v:55-83`
  选择单个 144 bit dirty/status wrapper。

### 3.3 地址和替换

默认配置下，tag index 是 `cmp_tag_index[8:0]`，tag data 来自地址高位；
`ct_l2c_tag.v:1044-1069` 对 16 个 way 做 tag 比较并与 valid/shared/
unique/dirty status 相与。`ct_l2c_cmp.v:747-770` 将 16 bit one-hot way
转换为 data index：高 4 bit 是 way，低位来自请求地址。

替换 way 是 `l2c_way_fifo` 与 `l2c_way_vld` 的组合。`ct_l2c_tag.v:1163-1197`
优先选择 `valid=0 && pending=1` 的 refill way；`ct_l2c_cmp.v:564-582`
从 FIFO way 取被替换 tag，`ct_l2c_cmp.v:789-805` 在替换行有效时发出
`CleanInvalid`（`snpl2`）请求并等待 CIU grant。

## 5. 一个普通访问的真实路径

### 5.1 CIU 到 bank

`ct_ciu_l2cif` 把 SNB0/SNB1 的请求分别映射为两个 bank 的 CIU 输入：

- 地址、13 bit type、CP set/clear、source、SID、HPCP 和 512 bit write data
  由 `snb0_l2c_*` / `snb1_l2c_*` 送入 bank 0/1，见
  `gen_rtl/ciu/rtl/ct_ciu_l2cif.v:670-713`。
- L2 地址 ready、completion、response、CP、SID、512 bit data 返回 SNB，见
  `:718-739`。
- DCA 请求按地址 bit 6 分 bank，见 `:1043-1049`；DCA 返回由两个 bank
  OR/select 回 CIU，见 `:743-748`。

在每个 sub-bank 中，`ct_l2c_tag` 先要求 ICC idle、WB-ECC RFIFO empty，
并排除与 tag/cmp/data stage 同一低位地址的冲突；满足条件后才拉高
`l2c_ciu_addr_ready_x`，见 `ct_l2c_tag.v:579-588`。

### 5.2 tag → compare → data → response

1. `ct_l2c_tag` 在 tag RAM 空闲时捕获 CIU 地址、SID、type、source、CP 和
   HPCP；tag/status RAM 由 ICC、compare、首个 CIU 请求和 WB 共同仲裁，见
   `ct_l2c_tag.v:594-617`。
2. tag stage 对 16 个 way 做 tag compare，形成 `v_hit/vd_hit/vs_hit/vu_hit`；
   compare stage 在 `ct_l2c_cmp.v:542-554` 解码请求类型。type 位定义为：
   read、allocate、clean、invalidate-clean、write shared/unique/dirty、
   atag、invalidate、release、unique、shared。
3. 命中读或 clean dirty line 产生 data read；写请求在 CIU data valid 后产生
   data write。`ct_l2c_cmp.v:717-738` 生成 data request，随后
   `ct_l2c_data` 用四个 slice 的相同 index 访问 512 bit line，见
   `ct_l2c_data.v:307-315`、`:374-406`。
4. data stage 将 SID/CP/response 和 line offset 保存，data access counter
   到 0 后锁存 `l2c_data_dout`，见 `ct_l2c_data.v:414-443`、`:495-528`。
5. `ct_l2c_wb` 把 data stage 输出送到 CIU，并用 3-entry、14 bit RFIFO
   排队 compare completion；`l2c_ciu_cmplt_x` 在 WB stage 或 RFIFO pop 时
   有效，见 `ct_l2c_wb.v:233-270`。

### 5.3 miss、replacement 和 refill

compare 的 `cmp_stage_refill = write && miss`，miss 时设置 valid；替换
way 从 FIFO/invalid way 选择。若待替换 way 有效，则 `ct_l2c_cmp` 通过
`l2c_ciu_snpl2_*` 发出 CleanInvalid 给 CIU/SNB，等待
`ciu_l2c_snpl2_ready_x`；见 `ct_l2c_cmp.v:631-648`、`:789-805`。

当前目录能确认的 refill 输入是 CIU 的 `ciu_l2c_data_vld_bank_*` 和
`ciu_l2c_wdata_bank_*`，并由 `ct_l2c_sub_bank.v:842-845` 接到 compare/data。
更上游的 line refill 产生、SNB 仲裁和 memory response 不在 L2C RTL 中。

## 6. 一致性、ICC、flush 和外部写回

### 6.1 状态位

每个 way 的 8 bit status 在 `ct_l2c_tag.v:1078-1167` 解包：

- bit 0：pending；bit 1：dirty；bit 2：shared；bit 3：valid；
- bit 7:4：4 bit CP；
- 另外的 16 bit FIFO 状态位来自 dirty SRAM 的 `[143:128]`。

compare 根据请求类型更新这些位：valid 在 refill/invalidate 时更新，dirty
在 write/clean/ICC 等路径更新，shared 在 shared/unique 请求时更新，pending
在 allocate/release/refill 时更新；详见 `ct_l2c_cmp.v:616-679`。

### 6.2 ICC 状态机

`ct_l2c_icc` 的状态包括 `ICC_STATE_IDLE`、`ICC_INV`、`TAG_RD`、`TAG_FLOP`、
`STATUS_UPDT`、`DIRTY_CHECK`、`WAIT_RDL`、`DATA_RD`、`DATA_FLOP`、
`DCA_RDY`、`DCA_CMPLT`，以及预留的 `DATA_CRRCT/TAG_CRRCT`，定义与转移在
`ct_l2c_icc.v:479-603`。

- CTCQ invalidate/clean、reset request、flush request 组合为 `inv_all`/
  `cln_all`，见 `:406-408`。
- ICC 从 index 0 递增到全 1，按 dirty-valid way one-hot 选择待处理 way，
  见 `:645-697`。
- dirty line 先产生 RDL 地址和 valid，等待 CIU `rdl_ready`，见 `:699-751`；
  data 由 `l2c_data_dout_flop` 提供。
- ICC 在 tag/status RAM 上写 invalidate/clean 状态，见 `:761-784`；DCA
  可读 tag、data、tag-ECC、data-ECC 四类数据，见 `:848-877`。

### 6.3 system flush

`ct_l2c_top` 只在 `sysio_l2c_flush_req && ciu_xx_no_op` 时进入 REQ，向两个
bank 同时广播 `l2c_flush_req_bank_*`；两个 bank 都完成后才进入 DONE，见
`ct_l2c_top.v:460-518`。sub-bank 的 ICC 将 flush 同时视作 clean 和 invalidate，
所以 dirty line 先经 RDL 写回，再清除 cache 状态。

### 6.4 CIU/VB/外部内存路径

L2C RTL 的外部接口命名全部是 `ciu_l2c_*` / `l2c_ciu_*`，没有
`biu_*` 端口，也没有直接的外部 memory AXI/总线端口。CIU 侧的证据是：

- prefetch 被编码为 ReadShared 请求送到 SNB，见
  `gen_rtl/ciu/rtl/ct_ciu_l2cif.v:1060-1086`；
- replacement CleanInvalid 被编码为 snoop 请求送到 SNB，见
  `:1088-1123`；
- ICC RDL 被编码为 WB request 送到 VCTM/VB，地址/valid/中间信息/512 bit
  write data 分别由 `l2c_ciu_rdl_*` 和 `l2c_ciu_data_bank_*` 提供，见
  `:1125-1184`。

因此，从本仓库可确认的层级是 `L2C → CIU l2cif → SNB/VB`；SNB/VB 再如何
连接到 BIU 或外部 memory，需要继续阅读对应 CIU/总线模块，不能从
`gen_rtl/l2c/rtl` 单独推断。

## 7. ECC、刷新、MBIST 与低功耗

### ECC 实现状态

- `ct_l2c_tag_ecc.v:222-281` 中 16 个 tag ECC decoder 以及 encode 相关
  实例都是注释。
- `ct_l2c_tag_ecc.v:328-362` 将 tag/dirty/FIFO 的 corrected 输出直接赋为
  原始 RAM 输出；`ct_l2c_tag_ecc.v:283-286` 将两半 fatal error 固定为 0。
- `ct_l2c_data.v:403-406` 把第五个 RAM select 输出为 `data_ecc_ram_cen`/
  `data_ecc_wen`，但 `ct_l2c_sub_bank.v:839-845` 只保留注释中的 ECC
  实例并没有连接 data-ECC RAM。
- `ct_l2c_icc.v:860-861` 的 DCA tag/data ECC 返回值固定为 0。
- `ct_l2c_wb.v:304-312` 的 WB tag/dirty request 和 WB-ECC RFIFO empty
  相关接口被固定为不活动/空。

### 低功耗和时钟

每个主要流水模块使用 `gated_clk_cell`，共同受 `l2c_icg_en` 和
`pad_yy_icg_scan_en` 控制；local enable 由请求、状态机忙状态或输出寄存器
有效产生。sub-bank 的总 gated clock 条件为 `ciu_l2c_data_vld_x | l2c_busy`，
其中 `l2c_busy` 汇总 tag/cmp/data/wb/RFIFO/ICC 状态，见
`ct_l2c_sub_bank.v:390-411`。

RAM clock-enable 由 tag/data 模块导出：
`l2c_tag_ram_clk_en_x = ~tag_cen_gate | ~dirty_cen_gate`，见
`ct_l2c_tag.v:855`；data 侧为五个 RAM enable 的 OR，见
`ct_l2c_data.v:401-406`。`l2c_xx_no_op` 是 prefetch idle 且两个 bank no-op
的组合，见 `ct_l2c_top.v:449`。

### MBIST / refresh

在 `gen_rtl/l2c/rtl` 文件清单和所有端口中没有 `mbist`/`bist`/memory-test
控制信号，也没有独立 refresh controller。`ciu_l2c_rst_req` 在 ICC 中被当作
全 cache invalidate 扫描请求，而不是 SRAM MBIST；证据为
`ct_l2c_icc.v:406-417`、`:455-475`。因此 MBIST、SRAM repair、物理 macro
refresh 若存在，应在本目录之外或由 memory macro/测试顶层提供。

## 8. 宏、平台和 wrapper 注意事项

- `ct_l2cache_*_array` 都用 `L2_CACHE_128K` 至 `L2_CACHE_8M` 宏选择实例；
  `ct_l2cache_tag_array_16way.v` 和 data/dirty array 的宏选择并不完全相同。
  特别是 dirty array 没有 `L2_CACHE_128K` 分支，见
  `ct_l2cache_dirty_array_16way.v:55-71`；128K/16-way 配置是否由上层禁止，
  仅凭本目录无法确认。
- 16-way 与 8-way 的参数分支都存在于 `cpu_cfig.h`，但本目录实际顶层实例
  固定为 `ct_l2cache_tag_array_16way` 和
  `ct_l2cache_dirty_array_16way`，见 `ct_l2cache_top.v:107-138`；8-way
  实例只出现在生成注释中。
- SRAM wrapper 的有效实现是 `ct_f_spsram_*`，其模块不在
  `gen_rtl/l2c/rtl`，而在 `gen_rtl/fpga/rtl` 等目录；例如 wrapper 在
  `ct_spsram_8192x128.v:64-72` 调用 `ct_f_spsram_8192x128`。TSMC instance
  只有注释，具体 ASIC macro 绑定无法由本目录确认。
- `MEM_CFG_IN` 只在 array wrapper 的条件编译连接中出现，见
  `ct_l2cache_data_array.v:90-99`、`ct_l2cache_tag_array_16way.v:82-91`、
  `ct_l2cache_dirty_array_16way.v:73-82`；其端口来源和宽度不在本目录中。
- data/tag setup 和 latency 来自 CIU，顶层把 setup+latency 限幅为最多 4/8
  cycle，见 `ct_l2c_top.v:398-447`；真正 SRAM 的同步读延迟要结合所选
  `ct_f_spsram_*` 或 ASIC macro 模型确认。

## 9. 无法仅凭本目录确认的事项

1. 普通 SNB 请求如何在 bank 0/1 间仲裁、SNB 的源端如何来自各 PIU/EBIU，
   不在 `l2c/rtl`；只能确认 CIU l2cif 已将 `snb0/snb1` 对称接入 L2。
2. L2 缺失 refill 数据的最终产生者、memory response 的时序，以及 RDL 经
   VCTM/VB 后到 BIU/外部 memory 的完整路径，需要 CIU、SNB、VB/BIU 文件。
3. `L2C_TAG_DATA_WIDTH` 是 tag payload 还是已包含某种 ECC 位，源码只按宏
   宽度切分；当前 ECC decoder 被注释，不能据此推断实际 parity/Hamming
   编码格式。
4. wrapper 中 `CEN/GWEN/WEN` 的物理有效电平和宏读延迟，需要 FPGA primitive
   或 ASIC SRAM macro 定义；L2 RTL 只在 data/tag 控制层做了反相和 setup
   flop 处理。
5. 128K/16-way 分支缺少 dirty 144-bit wrapper，是否由产品配置约束排除、
   是否由外部生成脚本补充，当前仓库的 `l2c/rtl` 无法确认。
