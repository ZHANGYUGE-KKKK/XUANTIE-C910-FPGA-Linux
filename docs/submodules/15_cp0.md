# CP0（特权、CSR、异常与低功耗）

## 1. 范围与结论

本文档基于 `gen_rtl/cp0/rtl` 下四个 RTL 文件的完整阅读，并沿端口名追踪到 `ct_core`、RTU、IFU、LSU、MMU、HAD、HPCP、BIU 及芯片顶层。本文描述的是当前 RTL 的真实行为，不对 RTL 作修改，也不把注释中未实现的功能当作已实现功能。

CP0 的职责可以概括为：

1. 接收 IDU 发出的 WFI、MRET、SRET 和 CSR 指令，完成权限检查、CSR 读改写、结果返回和非法指令异常。
2. 保存并输出机器/监管者特权状态、异常入口与返回信息、计数器权限、FP/向量状态、PMP/MMU/cache 控制及 C-SKY 扩展 CSR。
3. 汇聚 RTU 的同步异常、异步异常、提交/冲刷、返回和 dirty 更新，产生 IU 的异常/返回/flush 通知。
4. 汇聚 BIU、HPCP 和各执行单元的中断，按权限与 delegation 规则选出中断向量。
5. 协调 IFU、LSU、MMU 的 reset/invalidate/no-op 握手，并通过 LPMD 状态机实现 WFI 低功耗。

证据主要来自：`ct_cp0_top.v:15-1072`、`ct_cp0_iui.v:18-1656`、`ct_cp0_regs.v:18-4394`、`ct_cp0_lpmd.v:17-232`。

## 3. 顶层真实互联

### 3.1 CP0 在核心中的位置

`ct_core` 实例化 `ct_cp0_top`，CP0 使用 `forever_cpuclk` 和 `idu_rst_b`（接到 CP0 的 `cpurst_b`），扫描门控输入为 `pad_yy_icg_scan_en`。CP0 的完整连接段位于 `gen_rtl/cpu/rtl/ct_core.v:4485-4706`；RTU 紧邻其后实例化，并在 `:4711` 以后与 CP0 闭环。

```text
IDU CP0 decode/gateclk
          │
          ▼
       cp0_iui ───── CSR/L2/BIU/HPCP/MMU request ───► 外部单元
          │                         ▲
          │ result/expt/flush       │ cmplt/rdata/no-op
          ▼                         │
       cp0_regs ◄──── RTU exception/return/dirty/interrupt ack
          │
          ├── IFU/LSU/MMU/PMP/HPCP/IDU/IU 控制
          ├── HAD debug/CPUID/LPMD 信息
          └── cp0_yy_priv_mode、cp0_yy_clk_en、cp0_pad_mstatus
```

## 4. CSR 指令事务路径

### 4.1 IDU 到 IUI

IDU 的 CP0 选择来自 `ctrl_rf_pipe0_eu_sel[3]`，gateclk 选择来自 `ctrl_rf_pipe0_eu_gateclk_sel[3]`（`gen_rtl/idu/rtl/ct_idu_rf_ctrl.v:1407-1412`）。IUI 在 gateclk 周期锁存 WFI/SRET/MRET/CSR 标志、IID、opcode、src0 和目标物理寄存器（`ct_cp0_iui.v:735-782`）。

支持的 CP0 指令编码为：WFI、SRET、MRET、CSRRW、CSRRS、CSRRC 以及三种立即数形式，定义和译码见 `ct_cp0_iui.v:715-733`。CSR 地址取 `opcode[31:20]`，立即数取 `opcode[19:15]`，见 `ct_cp0_iui.v:784-803`。

IUI 采用 IDLE→EX1→EX2→EX3：

1. IDLE 等待 `idu_cp0_rf_sel`。
2. EX1 发出操作选择。
3. EX2 等待 `cp0_inst_cmplt`，并要求 RTU `commit0` 的 IID 与锁存 IID 相同。
4. EX3 返回 CSR 读结果，或完成 WFI/MRET/SRET。

状态机和 commit 约束见 `ct_cp0_iui.v:1078-1154`。CSR 写数据由操作类型决定：CSRRW 直接取 src0，CSRRS/CSRRC 使用读值 OR/AND-NOT，立即数形式使用 uimm，见 `ct_cp0_iui.v:1411-1448`。

### 4.2 地址、权限和只读检查

IUI 默认将 CSR 地址判为非法，仅开放标准 CSR、计数器、PMP 及若干 C-SKY 自定义地址段；自定义 M/S/U 段的范围判断见 `ct_cp0_iui.v:805-1076`。当前实现允许的主要自定义范围包括 M 的 `0x7c0-0x7ff`、`0xbc0-0xbff`、`0xfc0-0xfff`，S 的 `0x5c0-0x5ff`、`0x9c0-0x9ff`、`0xdc0-0xdff`，以及 U/计数器相关范围。

特权模式取自 `regs_iui_pm`：M=`2'b11`、S=`2'b01`、U=`2'b00`。S 模式受 `MSTATUS.TSR/TW/TVM`、S-counter 和 HPCP 权限约束；U 模式禁止 M/S CSR、MRET/SRET/WFI，并受 U-counter 约束。写只读 CSR、FS/VS 为 Off、TEE 权限不满足时均形成非法 CP0 指令，见 `ct_cp0_iui.v:1311-1380`。

CSR 事务的 BIU 编码为 `cp0_biu_op[15:8]` DCA 选择、`[7:4]` index、`[3]` write、`[2:0]` CSRRS/CSRRC/CSRRW 标记，见 `ct_cp0_iui.v:1450-1463`。HPCP 事务和等待条件见 `ct_cp0_iui.v:1472-1486`；最终完成条件见 `ct_cp0_iui.v:1488-1501`。

## 5. CSR 内容与状态输出

### 5.1 标准 CSR 覆盖面

IUI 的地址常量集中在 `ct_cp0_iui.v:429-708`，REGS 的本地 enable/decode 在 `ct_cp0_regs.v:1142-1437`。实际覆盖包括：

| 类别 | 主要 CSR | RTL 行为 |
|---|---|---|
| 机器识别 | `MVENDORID/MARCHID/MIMPID/MHARTID` | vendor=`64'h5b7`，MARCHID/MIMPID 为 0，MHARTID 取 BIU coreid，`ct_cp0_regs.v:1450-1487` |
| 机器状态 | `MSTATUS/MISA/MEDELEG/MIDELEG/MIE/MTVEC/MCNTEN` | 特权、异常 delegation、中断使能、入口基址、计数器权限，`:1490-1954` |
| 机器现场 | `MSCRATCH/MEPC/MCAUSE/MTVAL/MIP` | 异常入口保存与 CSR 读写，`:1957-2196` |
| 监管者状态 | `SSTATUS/SIE/STVEC/SCNTEN/SSCRATCH/SEPC/SCAUSE/STVAL/SIP/SATP` | 监管者状态、现场、入口、中断和地址转换，`:2198-2398`，SATP 下发 MMU |
| FP/向量 | `FFLAGS/FRM/FCSR/VSTART/VXSAT/VXRM/VL/VTYPE/VLENB` | FP 状态可更新；向量原始状态可存储，但有效输出存在固定值，见 `:2408-2627` |
| 计数器 | `MCYCLE/MINSTRET/MHPMCOUNTER*` 及 S/U 别名 | 地址检查和 HPCP 访问路径由 IUI/REGS/HPCP 共同完成，`:1936-1954`、`:3789-3977`、`ct_hpcp_top.v:22-32` |
| PMP/MMU | `PMPCFG/PMPADDR*`、`SATP` | PMP 输出到 IFU/LSU，SATP/MMU CSR 事务输出到 MMU，`:1166-1175`、`:4241-4277` |

### 5.2 C-SKY 扩展和缓存/调试 CSR

IUI 地址表还包含 `MXSTATUS/MHCR/MCOR/MCCR2/MCER2/MHINT/MRMR/MRVBR/MCER/MCNTWEN/MCNTINTEN/MCNTOF/MHINT2-4`、`MSMPR/MTEECFG`、`MCINS/MCINDEX/MCDATA0/1/MEICR/MEICR2`、`MCPUID/MAPBADDR/MWMSR` 以及 S 扩展和 FP 扩展地址，见 `ct_cp0_iui.v:429-708`。

REGS 中：

- `MXSTATUS` 保存当前 MPP/SPP、FS/XS/VS 等特权状态；`pm` 输出到各单元，见 `ct_cp0_regs.v:2630-2771`。
- `MHCR/MCOR` 控制分支预测和 cache invalidate；invalidate 完成后清对应控制位，见 `ct_cp0_regs.v:2773-2960`。
- `MHINT/MHINT2/MHINT3` 提供预取、局部 ICG、forwarding/ROB 等提示，超时默认值和写法见 `ct_cp0_regs.v:2962-3159`。
- `MRVBR` 在 IFU reset invalidate 请求期间采样 BIU RVBA，见 `ct_cp0_regs.v:3039-3065`。
- `MCINS/MCINDEX/MCDATA*` 形成 cache RAM 读操作；RID 映射 I-cache、D-cache、L2 tag/data 和 D-cache load tag，数据来自 IFU/LSU/BIU，见 `ct_cp0_regs.v:3218-3369`。
- `MCPUID` 支持 index 递增和多项 CPUID 字段；版本字段使用 `REVISION/SUB_VERSION/PATCH/PRODUCT_ID` 宏，见 `ct_cp0_regs.v:3372-3678`、`:3471-3486`。宏定义在 `gen_rtl/cpu/rtl/cpu_cfig.h:50-57`，当前值为 revision=1、sub-version=4、patch=3、product-id=0。

### 5.3 计数器与 HPCP

CP0 不在 REGS 内直接实现全部性能计数器，而是把 CSR 操作转成 HPCP 请求：`cp0_hpcp_sel/op/src0/wdata/index` 从 IUI/REGS 输出，HPCP 返回 `hpcp_cp0_cmplt/data/int_vld`。HPCP 接口声明见 `gen_rtl/pmu/rtl/ct_hpcp_top.v:22-32`、`:146-155`，核心实际连接见 `gen_rtl/cpu/rtl/ct_top.v:1862-1888`。IUI 在 `hpcp_cp0_cmplt` 到达前保持事务等待，见 `ct_cp0_iui.v:1488-1501`。

## 6. 异常入口、返回与中断

### 6.1 同步异常和非法 CP0 指令

RTU 在退休路径产生 CP0 异常输入：`rtu_cp0_expt_vld` 由同步/异步异常合成并屏蔽 debug mode，`rtu_cp0_epc` 按异常类型选择当前 PC 或下一 PC，`rtu_cp0_mtval` 直接传入，见 `gen_rtl/rtu/rtl/ct_rtu_retire.v:1295-1325`。

REGS 在非 delegation 异常时保存 M 态的 MEPC/MCAUSE/MTVAL，在 delegation 异常时保存 S 态对应现场；MSTATUS.MPIE/MIE、SSTATUS.SPIE/SIE、MPP/SPP 随入口更新，相关逻辑见 `ct_cp0_regs.v:1593-1709`、`:1975-2052`、`:2290-2398`。异常类型由 `MEDELEG` 和当前特权态决定，见 `ct_cp0_regs.v:1741-1791`。

IUI 的 CP0 权限异常用于 CSR 地址/写权限/FS/VS/TEE 检查失败：`cp0_ex2_expt_vld` 置位，`mtval` 使用原始 opcode，异常向量为 `5'h2`，见 `ct_cp0_iui.v:1546-1568`。CP0 指令选择同时产生 EX2 flush，并在 commit 相关时序下输出，见 `ct_cp0_iui.v:1629-1651`。

### 6.2 MRET/SRET

IUI 识别 MRET/SRET 并通知 REGS 更新 privilege/status；REGS 将返回 EPC 送给 IU：`cp0_iu_ex3_efpc` 在 MRET 时取 `mepc_value[39:1]`，SRET 时取 `sepc_value[39:1]`，valid 随返回指令产生，见 `ct_cp0_regs.v:4167-4173`。IUI 的 `cp0_mret/cp0_sret` 选择和 EX2 控制见 `ct_cp0_iui.v:1382-1408`。

### 6.3 中断汇聚、delegation 和向量

MIP 的外部源在当前 RTL 中为：

- `moip = hpcp_cp0_int_vld`；
- `meip = biu_cp0_me_int`、`mtip = biu_cp0_mt_int`、`msip = biu_cp0_ms_int`；
- `seip = biu_cp0_se_int || seip_reg`；
- `stip = biu_cp0_st_int && clintee || stip_reg`；
- `ssip = biu_cp0_ss_int && clintee || ssip_reg`；
- `mhip/mcip` 及 ECC 相关路径当前为 0。

证据见 `ct_cp0_regs.v:2055-2196`。REGS 先根据 MIE/SIE、MIDELEG、当前 privilege 和 custom enable 生成 `regs_iui_int_sel[14:0]`；IUI 再选最高优先级并输出 `cp0_rtu_xx_int_b`/`cp0_rtu_xx_int_vec`，见 `ct_cp0_regs.v:2187-2196`、`ct_cp0_iui.v:1577-1626`。

IUI 当前向量编码中包含：M external=11、M timer=7、M software=3、S external=9、S timer=5、S software=1，以及 HPCP/其他 custom 中断使用的 16/17/18；优先级 case 证据为 `ct_cp0_iui.v:1594-1610`。RTU 返回 `rtu_cp0_int_ack` 后，REGS/RTU 清理或推进对应中断处理。

## 7. WFI、reset invalidate 与低功耗

### 7.1 LPMD 状态机

`ct_cp0_lpmd` 的状态为 IDLE、WAIT、LPMD（`ct_cp0_lpmd.v:124-135`）：

1. WFI 在 EX1/EX2 被识别后，IDLE→WAIT。
2. WAIT 向 IFU、LSU、MMU、BIU 发出 no-op 请求；全部返回 ack 后进入 LPMD。
3. LPMD 等待 `cpu_in_lpmd` 被唤醒后回到 IDLE。

关键逻辑见 `ct_cp0_lpmd.v:136-190`。低功耗位 `lpmd_b` 在 ack 后由 WFI 设置为 `2'b00`，否则保持 `2'b11`；debug 或使能中断会恢复 `2'b11`，见 `ct_cp0_lpmd.v:198-214`。`cpu_in_lpmd = !(lpmd_b[1] & lpmd_b[0])`，`cp0_yy_clk_en = lpmd_b[1] & lpmd_b[0]`，见 `ct_cp0_lpmd.v:216-227`。因此 CP0 自身和全局模块的时钟门控是 WFI 握手完成后的结果，而不是看到 WFI 就立即关钟。

### 7.2 IFU/LSU/MMU reset invalidate

IUI 维护 cache/TLB reset invalidate 的独立等待状态：

- IFU 请求到达后等待 `ifu_cp0_rst_inv_done`；
- LSU 等待 `lsu_cp0_rst_inv_done`；
- MMU 等待 `mmu_cp0_tlb_done`；
- 三者全部 IDLE 后形成 `rst_inv_done`，并向 IFU/MMU 给出完成或 TLB-all-invalidate 信号。

证据见 `ct_cp0_iui.v:1156-1309`。IFU 的 reset vector 状态在 `gen_rtl/ifu/rtl/ct_ifu_vector.v:195-212` 产生 `ifu_cp0_rst_inv_req`，并在 `cp0_ifu_rst_inv_done` 后继续 PC load。对应完成信号在 LSU `gen_rtl/lsu/rtl/ct_lsu_icc.v:543-552`、MMU `gen_rtl/mmu/rtl/ct_mmu_regs.v:630-664`。

## 8. 时钟、复位和门控

### 8.1 CP0 时钟

IUI、REGS、LPMD 各自使用门控时钟单元；全局门控输入为 `cp0_yy_clk_en`，局部门控分别由 IUI 事务、REGS CSR/FESR/flush、LPMD 状态决定。

- IUI 的局部时钟使能包含 IDU gateclk、EX1/EX2/EX3、CSR EX2、flush、reset invalidate done、LSU/MMU done 和中断，见 `ct_cp0_iui.v:397-420`。
- REGS 的状态时钟由 CSR 选择或 IDU FESR 更新打开，见 `ct_cp0_regs.v:1050-1061`；vector、flush、cache-data 还有独立局部门控，见 `:1070-1133`。
- LPMD 的局部时钟在 WFI 执行或非 IDLE 状态保持打开，见 `ct_cp0_lpmd.v:136-145`。

### 8.2 复位和冲刷

CP0 使用 `cpurst_b` 低有效复位；`ct_core` 将 `idu_rst_b` 接给 CP0，见 `ct_core.v:4651-4652`。IUI/REGS/LPMD 的状态寄存器在复位或 RTU flush 时回到安全状态：IUI 回 IDLE，LPMD 回 IDLE，REGS 按各 CSR 的架构复位值初始化。RTU flush 还会参与 REGS 的 flush clock enable，见 `ct_cp0_regs.v:1092-1105`。

## 9. HAD、系统 IO 与顶层可见信号

HAD 看到的 CP0 信息包括 CPUID、IUI/LPMD debug state、LPMD bits 和 trace privilege write；`cp0_had_debug_info[1:0]` 来自 IUI 状态，`[3:2]` 来自 LPMD 状态，见 `ct_cp0_top.v:1061-1062`。HAD 对应端口在 `gen_rtl/had/rtl/ct_had_private_top.v:270`，`ct_core.v:1709-1723` 连接到 HAD 控制路径。

`cp0_pad_mstatus` 不是 sysio 内部 CSR 总线，而是 CP0/REGS 产生的 64 位状态输出：`ct_cp0_regs.v:4388` 将其赋为 `mstatus_value`，经 `ct_core.v:4630` 和 `ct_top.v:922` 逐级带到 CPU 顶层。单核外部端口声明见 `ct_top.v:230`；多核封装由 `openC910.v:62-178` 的 `core0_pad_mstatus` 等端口承接。因此当前 `ct_sysio_top.v` 没有独立的 CP0 CSR 连接，系统 IO 侧看到的是核心顶层导出的状态端口。

## 10. 当前 RTL 行为中的注意点

以下是阅读时确认的实现现状，均未在本次任务中修正：

1. `ct_cp0_regs.v:1372-1373` 的 `misa_local_en` 条件将地址与 `MCAUSE` 比较，代码形态与名称 `MISA` 不一致；这是当前 RTL 的可疑点，不能按预期行为推断。
2. 向量原始寄存器仍有存储/更新路径，但有效输出被固定或降级：`vs=2'b0`（`:1540`）、`vtype_vill=1` 且 `vsew/vlmul=0`（`:2589-2594`）、`vl=0`（`:2614`）、`vstart=0`（`:2546`）。
3. `HSTATUS/HEDELEG/VSSTATUS` 的实现值为 0，见 `ct_cp0_regs.v:3750-3785`；因此不能据地址表推断 hypervisor/virtual 状态已经可用。
4. MIP 中 `mhip/mcip` 和 ECC 中断相关实现当前为 0；实际有效外部源以 `ct_cp0_regs.v:2108-2117` 为准。
5. IUI 对某些自定义 CSR 采用地址范围放行，但 REGS 的显式 local enable、读 mux 或下游实现可能为空；应同时检查 `ct_cp0_iui.v:805-1076` 和 `ct_cp0_regs.v:1370-1437`、`:3835-3977`，不能只看 IUI 地址合法性。
