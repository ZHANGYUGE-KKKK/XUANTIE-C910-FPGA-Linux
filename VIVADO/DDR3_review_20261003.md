# 替换后 VCU118 FMC DDR3 工程复核

检查日期：2026-10-03 至 2026-10-04。检查对象为当前目录中的 C910_SOC.xpr、BD、相关 XCI、生成 HDL、XDC、软件地址配置、测试平台和现有构建日志；不沿用旧工程的器件、时钟或实例名结论。本次没有修改功能性工程文件。

## 结论

DDR3 的地址段已经分配；器件、容量、AXI 数据宽度及复位连接基本一致。但当前工程仍不能视为可上板版本：MIG 参考频率与输入不符、顶层仍使用 DDR4 约束，子板直插 J22 的 DQS/DQ 引脚分配不符合 MIG 规则，原板载 DDR4 参考时钟也位于另一 I/O 列。

## 1. 当前平台和存储器配置

- Vivado：2020.2；FPGA：`xcvu9p-flga2104-2L-e`。XPR、BD 和 DDR3 XCI 的器件一致。
- 顶层：`C910_SOC_wrapper`。当前生成 wrapper 已使用 `C0_DDR3_0_*` 和高有效 `sys_rst`，不是旧 DDR4 wrapper。
- README 仍写板载 DDR4，和当前 DDR3 BD 不一致，不可据此照搬板载 DDR4 配置。
- 子板原理图第 4 页标注 U26 为 `MT41K512M16`；目录中的另一份颗粒资料为 Alliance `AS4C512M16D3LB-12BCN/BIN`。实际焊接型号仍须以芯片丝印/BOM 为准。
- 两份资料的目标组织均为 512M x16，即 8 Gbit = 1 GiB；一组外部 CS、两个 DQS 和两个 DM，不应配置成 x32、两个外部 rank 或 8 GiB。

## 2. 地址警告的当前状态

当前 BD 中的地址段为：

- Master space：`/C910_core/m_axi`
- Master segment：`/C910_core/m_axi/SEG_DDR3_C0_DDR3_ADDRESS_BLOCK`
- Slave segment：`/DDR3/C0_DDR3_MEMORY_MAP/C0_DDR3_ADDRESS_BLOCK`
- Base：`0x0200000000`
- Range：`1G`，即 `0x40000000` bytes
- End：`0x023FFFFFFF`

`vivado.log` 的 BD 41-1356 出现在分配之前。第 227 行执行了 DDR3 `assign_bd_address`，之后重新生成的日志未再出现这一地址警告；当前 BD 和生成的 SmartConnect 地址解码也保留了该映射。因此“DDR3 尚未分配地址”不是当前保存设计的问题。

其它地址：BOOTROM `0x0 / 4K`，BRAM `0x10000 / 64K`，UART `0x40000000 / 4K`。1 GiB Linux 设备树 memory reg 与 DDR3 的 8 GiB 基地址、1 GiB 长度一致。

可在打开当前 BD 后用只读 Tcl 核实，无需重新分配或 exclude：

```tcl
set seg [get_bd_addr_segs /C910_core/m_axi/SEG_DDR3_C0_DDR3_ADDRESS_BLOCK]
get_property OFFSET $seg
get_property RANGE $seg
```

## 3. 未解决的参考时钟问题

### 频率不一致

`BADJ_CLK` 和 clk_wiz 的实际配置为 250 MHz，XDC 在 E12/D12 上建立 4.000 ns 时钟；但 DDR3 的 `C0.DDR3_InputClockPeriod` 为 13334 ps。`vivado.log` 第 240 行仍明确报 250.000 MHz 与 74.996 MHz 不一致。

当前 MIG 生成 MMCM 为 M=16、D=1、O=6，按约 75 MHz 输入设计。不能直接给它 250 MHz，也不能仅把 BD 的时钟频率标签改成 75 MHz 来消除警告。

本次在临时独立 BD 中、同一 Vivado 版本和 VU9P 器件上测试了 x16、1250 ps、AXI128/30、No_Buffer、输入 4000 ps。Vivado 接受参数并自动生成：

```text
C0.DDR3_InputClockPeriod = 4000
C0.DDR3_TimePeriod = 1250
C0.DDR3_CLKFBOUT_MULT = 4
C0.DDR3_DIVCLK_DIVIDE = 1
C0.DDR3_CLKOUT0_DIVIDE = 5
C0.DDR3_CasLatency = 11
C0.DDR3_CasWriteLatency = 8
```

即 250 x 4 / 1 / 5 = 200 MHz ui_clk。修改真实设计时应通过 MIG 参数界面重新选择参考输入速度，并让工具自动更新 M/D/O、重新生成输出，而不是手改生成 HDL。此独立测试的 DDR 和 AXI 接口未接完整，所以不把它的 BD 验证结果称为全工程通过。

### 物理时钟位置不匹配

对 VU9P 封装的独立 Vivado 查询结果：

| 引脚/区域 | Bank | Site / SLR |
| --- | --- | --- |
| E12 / D12 板载参考时钟 | 71 | IOB_X1Y650 / IOB_X1Y651；SLR_INDEX=2 |
| U35 / T36 子板 DQ0/DQ1 直插位置 | 45 | IOB_X0Y318 / IOB_X0Y319；SLR_INDEX=1 |
| V32 / U33 子板 DQS0 直插位置 | 45 | IOB_X0Y314 / IOB_X0Y315；SLR_INDEX=1 |

AMD PG150 要求 MIG MMCM 输入来自内存接口所在 I/O 列的 GCIO。若 DDR3 放在 J22 FMC 侧的 Bank 45 等区域，不能把 E12/D12 的旧 DDR4 时钟布局直接作为合规规划。4000 ps 只解决频率问题；必须为实际 DDR3 bank 规划合规参考时钟，随后由 implementation 验证。

## 4. DDR4 XDC 尚未迁移

工程唯一顶层 XDC 是 `C910_SOC.srcs/constrs_1/new/VCU118.xdc`。

- 内存约束仍全部引用 `C0_DDR4_*`，包含 64 DQ、8 DQS、DDR4 ACT/BG 等。
- 当前 wrapper 的内存端口是 `C0_DDR3_0_*`，x16/2 DQS，没有对应的 FMC DDR3 PACKAGE_PIN 约束。
- 电气标准仍是 SSTL12_DCI、POD12_DCI 和 DIFF_POD12_DCI；Bank 71/72/73 的 INTERNAL_VREF=0.6 也是原板载 DDR4 规划。
- DDR3 需要针对实际 FMC 接线和供电建立新约束；不可只把 DDR4 端口名批量改成 DDR3。
- 1.5 V 模式下通常应采用 MIG 生成的 SSTL15_DCI/DIFF_SSTL15_DCI 标准、合适的 VREF=0.75 V，并检查 VRP/DCI 支持。实际设定须与板上 VCCO、外部 VREF/终端方案相符。
- 现有 C910 JTAG 使用 FMC bank 的 LVCMOS18 引脚。若调整共享 FMC VADJ，须同时检查 JTAG 电平、外部适配器及各 bank 供电，不能只修改 DDR IOSTANDARD。
- sys_rst 的 L19 高有效 SW5，以及独立 UART 的 AW25/BB21，不属于上述 DDR4 内存约束替换问题。

## 5. 子板直接插 J22 不满足 MIG 数据引脚规则

对子板原理图第 4 页、VCU118 原理图第 34–35 页及官方板级 XDC 的交叉核对，低字节的部分直插连线如下：

| 子板信号 | FMC 触点 | J22 信号 | FPGA 引脚 | FPGA 功能 |
| --- | --- | --- | --- | --- |
| DDR3_D0 | G30 | LA29_P | U35 | Bank45 T0U_N6，专用 DQS/DBC 位置 |
| DDR3_D1 | G31 | LA29_N | T36 | Bank45 T0U_N7，专用 DQS/DBC 位置 |
| DDR3_DQS_P0 | D26 | LA26_P | V32 | Bank45 T0L_N2，普通数据位置 |
| DDR3_DQS_N0 | D27 | LA26_N | U33 | Bank45 T0L_N3，普通数据位置 |

对于 x16 DDR3，DQS 必须位于对应 byte lane 的 N6/N7；DQ 必须在同一 byte lane 的其它允许位置，DM 在 N0。上述接法中 DQS0 落在 N2/N3，而 DQ0/DQ1 占据 N6/N7，因此直接插 J22 不能用常规 MIG x16 引脚配置解决。这里不是把 T0L 和 T0U 误认为不同 byte lane；它们同属 T0，错误是专用引脚位置。

必须用符合 MIG 规则的转接/重排方案，或更换接线兼容的硬件。若已有转接板，应以转接板的实际网表重新做完整 DQ/DQS/DM、地址控制、CK、bank/SLR、供电及参考时钟核对；不能拿上述直插表当成转接后的最终 XDC。仅软件重命名、任意 DQ/DQS 交换或降低频率不会改变专用引脚规则。

## 6. AXI、复位和其它一致性检查

- C910 128-bit AXI -> SmartConnect M02 -> axi_clock_converter_1 -> DDR3，连接链路存在。
- CPU/SmartConnect/转换器 S 侧为 100 MHz；转换器 M 侧使用 DDR3 ui_clk（目标 200 MHz）。
- MIG `c0_ddr3_ui_clk_sync_rst` 经过反相，驱动 MIG `c0_ddr3_aresetn` 与转换器 M 侧复位，逻辑极性一致。
- SW5 的高有效 `sys_rst` 直接到 clk_wiz/reset 和 DDR3/sys_rst；经反相到 rst_sys_clk/ext_reset_in。该 reset IP 的 `C_EXT_RESET_HIGH=0`，因此此处并非复位极性错误。
- reset IP 的 `C_AUX_RESET_HIGH=0`，aux_reset_in 接常数 1；mb_debug_sys_rst 接常数 0，均为不触发状态。
- 转换器保留 33-bit 地址，生成 HDL 进入 MIG 时取 `[29:0]`。SmartConnect 先用系统地址解码 DDR3 区域，且 DDR3 基地址按 1 GiB 对齐，所以这不是单凭位宽差异即可认定的错误；不应机械地把 CPU、SmartConnect、转换器都改成 30-bit。
- C910 IP XML 引用的 863 个文件在当前仓库均存在。
- BOOTROM 为 4 KiB、BRAM 为 64 KiB，地址 slice `[11:4]` / `[15:4]` 与 128-bit 存储组织对应；初始化 COE 文件存在。
- UART 115200、100 MHz 参数与系统时钟一致。
- `c0_init_calib_complete` 未接到可观测状态出口；无 DDR ILA。建议上板时至少观测校准状态、ui_clk_sync_rst 和 AXI 握手，便于区分校准失败与 CPU/软件问题。未导出校准状态不是单独证明功能必然失败的依据。

## 7. 验证完成度与下一步

- 原工程 DDR3 IP 的 OOC synth 在 2026-10-03 23:46:46 成功结束：0 errors、0 critical warnings；有普通 warnings。转换器 OOC 综合也已成功。
- 检查时 C910 核心 OOC 综合仍在运行；没有已完成的全系统 synth_1、impl_1、布线时序/DRC/bitstream 结果。因此不能将 IP 综合成功等同于系统可上板。
- 工程 sim_1 未登记现有 testbench，顶层为 wrapper。磁盘上的 DDR/UART TB 仍用 DDR4 端口、sys_rstn 和 200 MHz 输入，和当前 DDR3/高有效 sys_rst/250 MHz 输入不兼容，尚无当前 DDR3 系统仿真通过证据。
- 直接以 read-only 模式打开原项目时，Vivado 锁住 BD；尝试复制 BD 的诊断受到复制后 COE/IP 相对路径影响，未取得本次新的全 BD 动态验证通过结果。上述副本问题不作为原工程缺陷。地址结论依据当前 BD、生成解码及最新原工程日志；额外动态测试仅确认独立 MIG 的 250 MHz 参数可接受及封装属性。

建议顺序：先确认实物颗粒和转接/供电方案，完成满足 MIG 规则的 FMC 引脚及同列参考时钟规划；再更新 MIG 参考频率与 DDR3 XDC、重新生成输出；修订 DDR3 TB；最后跑全系统综合、implementation、DRC/时序，并在硬件验证校准状态和 DDR 读写回环。
