# C910 FPGA 烧录与启动说明

## 1. 当前“烧录”方式

当前 FPGA 工程的启动方式是 BootROM/BRAM 启动后，通过 JTAG 把各阶段镜像加载到
DDR。镜像断电后不会保留，因此严格来说属于易失性下载，不是写入 SPI Flash、
eMMC 或 SD 卡的永久烧录。

板上电前应确保：

- 已下载当前 C910 SoC FPGA bitstream；
- DDR4 初始化和校准成功；
- BootROM/BRAM stub 能运行并停在 JTAG 调试点；
- 串口参数为 `115200 8N1`；
- GDB 已连接到目标核并停止 CPU。

## 2. 镜像和地址

| 镜像 | 加载地址 | 用途 |
| --- | --- | --- |
| `opensbi-c910-fpga-fw_jump.bin` | `0x200000000` | M 模式固件 |
| `u-boot-c910-soc-minimal.bin` | `0x200200000` | U-Boot |
| `linux-c910-fpga-Image.bin` | `0x200600000` | Linux 5.10 Image |
| `rootfs-c910-lite.cpio.gz` | `0x204000000` | JTAG initramfs 根文件系统 |
| `c910-soc-system.dtb` | `0x210000000` | OpenSBI、U-Boot、Linux 共用 DTB |

当前 initramfs 结束地址是 `0x2056e17de`。该地址已经写入同目录的 DTB。
更换 rootfs 后必须重新执行：

```bash
./build-c910-fpga-complete.sh package
```

## 3. 下载前校验

在 `complete-image` 目录执行：

```bash
sha256sum -c SHA256SUMS
```

所有项目都应显示 `OK`。

## 4. 新版镜像的推荐启动流程

以下流程同时加载 OpenSBI、U-Boot、Linux、initramfs 和系统 DTB。
它是当前 `complete-image` 的唯一推荐流程。

1. 上电并下载与当前硬件配置对应的 FPGA bitstream。
2. 打开 `115200 8N1` 串口，等待 BRAM stub 输出 `LINUX_BOOT_STUB_READY`。
3. 连接 JTAG server，让 CPU 停在 BRAM stub 的 `ebreak` 处。
4. 在主机上先校验整包镜像：

   ```bash
   cd /home/lhb/linux/c910/FPGA配置/complete-image
   sha256sum -c SHA256SUMS
   ```

5. 启动对应的 RISC-V GDB，连接并停止目标核：

   ```gdb
   target remote <JTAG服务器地址:端口>
   monitor halt
   source load-c910-complete.gdb
   ```

6. 脚本完成五个镜像的 DDR 下载、入参设置和 `continue`。不要在
   `source` 命令后再手动修改 PC 或 MAEE。
7. 串口上检查 OpenSBI 显示的下一级信息：

   ```text
   Domain0 Next Address : 0x0000000200200000
   Domain0 Next Arg1    : 0x0000000210000000
   ```

8. U-Boot 停在命令行时执行：

   ```text
   booti 0x200600000 - 0x210000000
   ```

   如果 U-Boot 已配置自动执行该命令，则无需重复输入。

9. 验收时应当看到 Linux 越过 `Starting kernel ...`，最后出现 `hvc0`
   登录终端。

### 新版流程不再需要的操作

- 不再用 GDB 手动清除 `MXSTATUS[21]` 或 `SXSTATUS[21]`；
- 不再加载 `u-boot-c910-soc-minimal.dtb` separate DTB；
- 不再向 U-Boot 的某个内部固定地址 restore DTB；
- JTAG initramfs 启动不加载 `rootfs-c910-lite.ext4`。

## 5. GDB 脚本所做的事

先进入镜像目录，再启动对应的 RISC-V GDB：

```bash
cd /home/lhb/linux/c910/FPGA配置/complete-image
```

在 GDB 中连接 JTAG server，例如：

```gdb
target remote <JTAG服务器地址:端口>
monitor halt
source load-c910-complete.gdb
```

`load-c910-complete.gdb` 会依次加载五个镜像，设置：

```text
a0 = 0
a1 = 0x210000000
pc = 0x200000000
```

然后执行 `continue`。

## 6. 手动下载命令

不使用脚本时，在 GDB 中执行：

```gdb
restore opensbi-c910-fpga-fw_jump.bin binary 0x200000000
restore u-boot-c910-soc-minimal.bin binary 0x200200000
restore linux-c910-fpga-Image.bin binary 0x200600000
restore rootfs-c910-lite.cpio.gz binary 0x204000000
restore c910-soc-system.dtb binary 0x210000000

set $a0 = 0
set $a1 = 0x210000000
set $pc = 0x200000000

x/4i 0x200000000
x/4wx 0x210000000
continue
```

DTB 地址处的首字应显示为：

```text
0xedfe0dd0
```

这是 DTB magic `0xd00dfeed` 的小端显示。

## 7. 启动链路

正常链路为：

```text
BootROM/BRAM stub
  -> OpenSBI 0x200000000
  -> U-Boot  0x200200000
  -> Linux   0x200600000
  -> initramfs 0x204000000
```

U-Boot 默认命令为：

```text
booti 0x200600000 - 0x210000000
```

initramfs 起止地址由 DTB 的 `/chosen/linux,initrd-start` 和
`linux,initrd-end` 提供，因此 U-Boot 命令中的第二个参数保持 `-`。

新 U-Boot 使用 OpenSBI 在 `a1` 中传入的系统 DTB，不要再加载旧的
`u-boot-c910-soc-minimal.dtb` separate DTB。

OpenSBI 在 early init 中清除 C910 MAEE，然后以 `a0=0`、
`a1=0x210000000` 跳转 U-Boot。U-Boot 继续使用该 DTB 启动 Linux。

## 8. 串口输出

OpenSBI 和 U-Boot 直接使用地址 `0x40000000` 的 Xilinx UARTLite。
UARTLite 中断在当前 Vivado BD 中没有连接到 PLIC，因此 Linux 使用：

```text
console=hvc0 earlycon=sbi
```

Linux 和用户空间通过 SBI console 输出到同一个 UARTLite。根文件系统已经配置：

```text
hvc0::respawn:/sbin/getty 115200 hvc0
```

## 9. ext4 根文件系统

`rootfs-c910-lite.ext4` 用于以后接入 SD、eMMC、NVMe 或其他块设备时烧录，
不能在当前流程中直接替换 `rootfs-c910-lite.cpio.gz` 加载到 DDR。

要从 ext4 启动，还需要同时具备：

- FPGA 中实际存在并连接对应块设备控制器；
- Linux DTB 中包含该控制器节点；
- Linux 内核启用对应驱动；
- U-Boot bootargs 改为正确的 `root=/dev/...`。

当前硬件资料没有定义可供永久启动使用的 SPI Flash/eMMC 分区，因此不要把本文中的
DDR 地址当作 Flash 烧录偏移。永久烧录方案必须根据最终 FPGA 外设和存储器连接另行制定。

## 10. 常见检查

OpenSBI 无输出时，检查 DTB 是否位于 `0x210000000`，以及是否使用了禁用
semihosting 的新版 OpenSBI。

本镜像中的 OpenSBI 会在 C910 FPGA early init 中清除
`MXSTATUS[21]`/`SXSTATUS[21]` 的 MAEE 位。如果 Linux 仍停在
`Starting kernel ...` 并出现 S-mode Store/AMO access fault，先确认加载的
`opensbi-c910-fpga-fw_jump.bin` 与本目录 `SHA256SUMS` 一致，不要再额外手动清 CSR。

U-Boot 显示 `devicetree: separate` 时，说明加载了旧版 U-Boot；新版应使用前级传入
的 DTB，通常显示 `devicetree: board`。

Linux 能打印但没有登录终端时，检查 bootargs 是否为 `console=hvc0`，并确认 rootfs
中的 `/etc/inittab` 包含 `hvc0` getty。
